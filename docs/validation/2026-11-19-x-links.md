# Native X post IDs and URLs

Milestone 4 adds explicit native link capture through the existing account-verified Phone session.
The service reads the selected post's Share control, chooses Copy link once, verifies a fresh Android clipboard receipt, and rechecks the original browsing occurrence before returning a result.
No OCR, network resolution, recipient selection, or content submission is involved.

## Interface and evidence contract

`X.copy_link()` returns an immutable `PostLink` with `source_key`, `author`, `post_id`, and `url`.
`XBrowser.copy_link(observation)` first checks the supplied observation identity and retains the verified link for subsequent observations of that occurrence.
`PostObservation.native_post_id` and `PostObservation.post_url` default to `None` and remain separate from local `identity` and `source_key` values.
Passive observations do not open Share or infer native identity from text, timestamps, local hashes, or quoted content.
Starting another workflow, advancing, engagement that selects a successor, and caption expansion clear the retained link.

The shared URL interpreter accepts direct HTTPS author/status links on X and Twitter host aliases, validates the decimal native ID, and removes share tracking and fragments.
Authorless status routes, shortened links, foreign hosts, credentials, explicit ports, malformed IDs, and attachment paths remain unsupported.
The copied link's author must match the selected outer author.
Quoted content and local content keys never supply a missing native ID.

The native Share reader requires one Copy link label in the observed action row beside Share via.
It excludes nested controls and the sheet's dismissal padding from tap regions.
The service rereads those controls before copying and requires the Share surface to contain no old clipboard receipt.
Only a subsequently observed native Android clipboard receipt can supply the URL, so copying the same link again does not rely on a changed clipboard string.
The full native preview value is receipt metadata; it is not a claim that the narrow preview visually displays every URL character.
The clipboard window remains an occlusion for content extraction and gestures, and unknown system overlays remain unsupported.

Success requires the exact source content, author, geometry, selected occurrence, and browsing query/tab to remain verified, including a final reread.
Missing receipts, changed targets, mismatched authors, or failed returns invalidate browsing without retrying Share or Copy link.
Failure cleanup can dismiss a recognized Share sheet once and preserves the original error or cancellation if restoration also fails.
Explicit `start` recovery dismisses a retained recognized Share sheet before drawer account verification.
Deadlines, cancellation, reservations, locks, and keyboard restoration remain owned by the existing Phone session.

## Physical validation

Direct implementation run `20261119T203818.638521Z` passed on Nir's Pixel 4a `0A031JEC221805`, Android 13, X `12.42.0-prod.01`, English UI, at 1080 × 2340.
It verified `@NirGalel`, searched Top for `from:NASA "stellar merger"`, and selected the NASA stellar-merger image post.
The first and repeated calls returned native ID `2123169377855922254` and `https://x.com/NASA/status/2123169377855922254`.
Both calls preserved the original observation identity, content key, and caption.
The repeated copy followed receipt expiry and verified a new native receipt for the same URL.
The run restored the original Gboard input method, completed Phone cleanup, and released its locks.
No phone session remains active from this run.

Raw evidence remains local under `tests/smoke/x-link-runs/20261119T203818.638521Z/`.
Its result, 31 hierarchy reads, source/return captures, native Share capture, and native receipt capture record the workflow.
The fixture manifest links four successful-run captures and four earlier Latest discovery captures to their original hashes.
Earlier discovery on the unrestricted latest NASA feed encountered unsupported media-tag content, and the date-bounded query selected a post whose Share footer was offscreen.
Those cases stopped without copying and remain coverage limits rather than successful link validations.
The Latest Copy link discovery produced the native URL before the clipboard-overlay reader existed, so that discovery does not establish a verified return.

Human screenshot review is pending and remains separate from native XML and replay verification.

General advertising recognition, remaining layout/traversal validation, and other outstanding screenshot reviews remain outside this milestone.
